# CaiBotWindy QQ 机器人上架手册

> 目标：让机器人在 QQ 群 / 单聊里对所有用户可用（从沙箱到正式上线）。
> 全部操作在 QQ 开放平台管理端（https://q.qq.com）完成，必须用超级管理员 QQ 扫码登录。
> 本文档里带 `复制` 标记的内容可以直接粘贴到平台表单。

---

## 一、上架前自检

### 1. IP 白名单

平台对新增机器人默认启用 IP 白名单，官方原文：

> 对于新增机器人，平台默认启用 IP 白名单功能，并限制只有填写了 IP 白名单才能提审和上线。

- 入口在机器人管理端 → `开发设置` → `IP 白名单`
- 填本机的公网出口 IP。这台机器在 NAT 环境，公网 IP 为 `43.226.128.77`（内网 172.16.0.76）。暂时不确定的话，先访问 https://myip.ipip.net 确认，以查到的为准
- 启用后，只有白名单 IP 才能连 WebSocket 和调用 OpenAPI。机器人所在的这台机器就是出口，填它就对了
- 沙箱环境不受影响（白名单只作用于正式环境），所以沙箱里测通了不代表上线后能连，上线前一定要填

### 2. 沙箱环境先跑通

- 在管理端 `开发设置` → `沙箱配置` 里配好沙箱群（必须是你自己是群主/管理员的群，成员 ≤ 20 人）
- 把机器人加进沙箱群，把自测报告里要填的每条指令都真跑一遍
- 正式群只允许使用「已审核通过并上线」的功能，所以沙箱这一步是唯一能提前验证的机会

### 3. 机器人基础信息

- `开发设置` → 基础信息：名称、头像（正方形）、简介
- 首次上线前，基础信息会随功能配置一并提审；首次上线后改基础信息要单独提审，且每月限改 5 次
- 名称里不要带特殊符号，否则可能创建失败

## 三、使用范围与人员

- 入口在 `发布设置` → `使用范围与人员`
- 全部场景（频道 / 群 / 单聊）都设为「全部」，官方指南明确要求这样操作才能上线
- 注意：机器人首次上线前，从「全部」切到「白名单」要等审核；上线后「全量 → 白名单」立即生效，反方向才要审核

## 四、自测报告（必交）

平台要求下载官方模板填写后上传：

- 模板：机器人自测报告.xlsx（管理端 `发布设置` 页面可下载）
- 填写要点：
  1. 逐条测试你在「指令配置」里登记的指令，记录是否正常响应
  2. 如果某条指令需要参数（例如 `/查背包 <玩家名>`、`/注册 <QQ邮箱> <角色名>`），务必在「特殊说明」栏写清楚。官方审核照着你填的清单去测，缺参数说明会被判失败
  3. 测试环境写沙箱群

建议在特殊说明里补充的内容（可直接复制）：

```
【需要参数的指令清单】
1. /查背包 <玩家名>       —— 需真实在线的玩家角色名，服务器无人在线时会提示无数据
2. /注册 <QQ邮箱> <角色名> —— 邮箱仅支持 @qq.com 与 @foxmail.com，会发送 6 位验证码
3. /注册验证 <验证码>      —— 配合 /注册 使用
4. /排行 <类型>           —— 类型可选（如 金币 等），不带参数会列出可选类型
5. /服务器信息 <序号>      —— 序号由 /服务器列表 得到
6. /远程指令 <指令>        —— 需要管理员权限
7. /si、/sn、/sp、/sb、/sx <名字或ID> —— 后跟物品/生物名，例如 /si 泰拉

【权限说明】
- 白名单相关、进服登录审批等指令需要「机器人管理员」权限，普通用户会收到权限不足提示
- 首次进服会记录设备与 IP 作为基准，之后换设备会自动推送到群里由管理员确认

【依赖说明】
- 机器人需与 TShock 服务端位于同一台机器（或能访问其日志目录）
- 服务器需在群里通过 /添加服务器 <IP> <端口> <绑定码> 完成绑定后才能查询数据
```

## 五、隐私协议（必交）

平台要求上传第三方机器人隐私保护指引（管理端 `发布设置` 可下载模板 `.docx`）。

CaiBotWindy 涉及的用户数据（照实填写即可）：

| 收集项 | 用途 | 存储位置 |
|---|---|---|
| QQ OpenID | 标识操作者、判定群管理员、云黑名单 | 服务器本地 `store.json` |
| 群 OpenID | 绑定群与服务器、父子群关系 | 服务器本地 `store.json` |
| 游戏角色名 | 白名单绑定 | 服务器本地 `store.json` |
| 登录 IP / 设备 UUID | 进服身份校验（防冒用） | 服务器本地 `store.json`，每项保留最近 8 条 |
| QQ 邮箱 | 注册验证（仅发送验证码） | 只存角色与邮箱的绑定关系 |

可以写进隐私协议的说明（可直接复制）：

```
本机器人收集的信息仅用于提供游戏服务器管理服务：
1. QQ OpenID：用于识别操作者身份、判定群管理权限、维护黑名单；
2. 群 OpenID：用于将群与游戏服务器建立绑定关系；
3. 游戏角色名：用于白名单校验；
4. 进服 IP 与设备标识：用于识别是否本人登录，防止账号被冒用；
5. QQ 邮箱：仅用于发送一次性验证码完成角色注册，不作营销用途。

以上信息全部存储于机器人运营者自有的服务器中，不向任何第三方共享、
不用于广告推送。用户可通过群内指令或联系管理员申请删除自己的数据。
```

## 六、提交审核 → 上线

1. `发布设置` → 点击提交审核，上传自测报告与隐私协议
2. 审核时效：当日 16:00 前提审当日审完，16:00 后次日审完
3. 审核通过后，回到 `发布设置` → 点上线机器人
4. 上线后才能在非沙箱的群 / 单聊里被添加使用

> 审核过程中不可重复提交。若被驳回，点右上角「通知」查看原因，改完再提。

---

## 七、上线后的运维检查

上线前请确认：

- [ ] IP 白名单已填 `43.226.128.77`（否则正式环境连不上，机器人会「上线了但不回话」）
- [ ] 机器人与 TShock 服务端的计划任务都是开机自启（`Windy Bot` / `TShock Server`）
- [ ] `Windy Bot` 启动脚本里的 `DOTNET_ROOT` 指向 `dotnet-sdk\`（已配）
- [ ] 群内 `/添加服务器` 绑定流程可用
- [ ] 端口 `7777`（游戏）与 `22338`（机器人 HTTP）在云安全组 + Windows 防火墙都已放行（已配）

## 附：常见驳回原因对照

| 驳回原因 | 处理 |
|---|---|
| 机器人名称违反平台规范 | 去掉特殊符号 / 敏感词，名称≤12 字 |
| 指令测试不通过 | 检查自测报告里的「特殊说明」是否把需要参数的指令写全了 |
| IP 白名单未配置 | 填公网出口 IP |
| 使用范围未设为全部 | `使用范围与人员` 三个场景都改成「全部」 |
| 功能与介绍不符 | 精简指令介绍，别写没实现的功能 |
