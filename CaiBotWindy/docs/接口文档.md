## 1. 概述

### 1.1 系统定位

CaiBotWindy 是运行于 [Windy](https://github.com/) 机器人框架的 QQ 官方机器人插件，内置一个兼容 CaiBotLite 协议的
HTTP / WebSocket 服务端，供 TShock 侧适配插件主动连入。

职责分两类：

| 职责 | 说明 |
| --- | --- |
| 面向玩家 / 管理员 | 在 QQ 群里以指令方式查询服务器状态、管理白名单、审批入群 |
| 面向服务端 | 接收 TShock 适配插件的长连接，转发 RPC 查询与白名单校验 |

### 1.2 架构

```
┌──────────────┐   QQ 官方协议    ┌────────────────┐  HTTP / WebSocket  ┌─────────────────┐
│  QQ 群 / 用户 │ ◄──────────────► │  CaiBotWindy   │ ◄────────────────► │ TShock 服务端    │
└──────────────┘   指令 / 卡片     │  （本插件）     │   CaiBotLite 协议  │ （适配插件）      │
                                   └────────────────┘                    └─────────────────┘
                                          │
                                          ▼
                                   store.json / CaiBotWindy.json
                                   （原子写入 + 自动备份）
```

### 1.3 接口分类

| 分类 | 消费者 | 章节 |
| --- | --- | --- |
| HTTP 接口 | TShock 适配插件、QQ 平台 | [§3](#3-设备端接口--http) |
| WebSocket 接口 | TShock 适配插件 | [§4](#4-设备端接口--websocket) |
| 数据包协议 | TShock 适配插件 | [§5](#5-数据包协议) |
| QQ 指令接口 | QQ 群用户 / 管理员 | [§7](#7-qq-指令接口) |
| 配置接口 | 运维人员 | [§8](#8-配置接口) |
| 运维诊断接口 | 管理员 | [§9](#9-运维与诊断接口) |

## 2. 通用约定

| 项目 | 约定 |
| --- | --- |
| 字符编码 | UTF-8 |
| 时间格式 | 落盘与传输用 UTC（`DateTime.UtcNow`）；面向用户展示时转本地时间 |
| 群标识 | `group_open_id`（QQ 群 OpenID，32 位十六进制大写字符串） |
| 用户标识 | `member_open_id` / OpenID。**QQ 官方机器人只能拿到 OpenID，永远拿不到真实 QQ 号** |
| 场景 | `Group`（群聊）、`GroupAt`（群内 @ 机器人）、`Private`（私聊） |
| 默认监听 | `http://+:22338/`（可用 `+` 表示全部网卡） |
| 单帧上限 | 发往服务端的包软上限 1000 字节（`MaxOutgoingFrameBytes`），超出会在控制台告警 |

## 3. 设备端接口 · HTTP

### 3.1 接口总览

| # | 方法 | 路径 | 用途 | 鉴权 |
| --- | --- | --- | --- | --- |
| 1 | GET | `/ping` | 健康检查 | 无 |
| 2 | GET | `/server/token/{init_code}` | 用绑定码换取连接令牌 | 绑定码 |
| 3 | GET | `/download/{file_id}` | 下载临时文件（地图 / 小地图） | file_id |
| 4 | GET | `/plugin/{name}` | 下载 plugins 目录下的插件文件 | 无 |
| 5 | GET | `/assets/{path}` | 图鉴素材（物品 / 生物图标） | 无 |
| 6 | GET | `/{appid}.json` | QQ 侧域名校验 | 无 |
| 7 | WS | `/server/ws/{group_open_id}/{server_type}/` | 服务端长连接 | Bearer Token |

---

### 3.2 `GET /ping`

健康检查。

请求参数：无

响应：`200 OK`

```json
{ "result": "pong" }
```

---

### 3.3 `GET /server/token/{init_code}`

服务端用绑定码换取 WebSocket 连接令牌。绑定码由 TShock 侧适配插件生成并打印在控制台。

路径参数

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `init_code` | string | 绑定验证码（`/添加服务器` 时登记） |

响应：`200 OK`

```json
{
  "token": "c0ffee...",
  "group_open_id": "82DBCB8DB5A3DDC96A7933D3D1FCFC41"
}
```

错误码

| 状态码 | 触发条件 |
| --- | --- |
| `404` | 绑定码为空 / 不存在 / 已过期（超过 `BindCodeLifetimeMinutes`，默认 30 分钟） |

副作用：首次换取成功时把该服务器记录标记为 `Bound = true` 并落盘。

---

### 3.4 `GET /download/{file_id}`

下载机器人托管的临时文件（世界文件 `.wld`、小地图 `.tmap`）。

路径参数

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `file_id` | string | 由 RPC 响应返回的文件 ID（URL 编码） |

响应：`200 OK`

- `Content-Type: application/octet-stream`
- `Content-Disposition: attachment; filename="<文件名>"`

错误码

| 状态码 | 触发条件 |
| --- | --- |
| `404` | 文件不存在或已过期（`DownloadFileLifetimeMinutes`，默认 10 分钟） |

---

### 3.5 `GET /plugin/{name}`

下载 `Plugins/` 目录下的插件文件，不允许子目录。

路径参数

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `name` | string | 文件名（URL 编码） |

响应：`200 OK`，`application/octet-stream`

错误码

| 状态码 | 触发条件 |
| --- | --- |
| `403` | 路径含 `/`、`\` 或 `..` |
| `404` | 文件不存在，或解析后越出 plugins 目录 |

---

### 3.6 `GET /assets/{path}`

图鉴素材（物品 / 生物图标）。与 `/plugin/` 不同，允许子目录（如 `Items/Item_39.png`）。
QQ 服务端会主动拉取并转存，因此 http + 裸 IP + 非标端口即可，不要求 HTTPS。

路径参数

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `path` | string | 相对素材根目录的路径（URL 编码） |

响应：`200 OK`

- `Content-Type` 按扩展名推断（`.png` / `.jpg` / `.gif` / `.webp` / `.bmp`，其余 `application/octet-stream`）
- `Cache-Control: public, max-age=86400`

错误码

| 状态码 | 触发条件 |
| --- | --- |
| `403` | 路径段为空、`.`、`..` 或含非法文件名字符 |
| `404` | 素材根目录未配置、路径为空、越出根目录、或不是文件 |

---

### 3.7 `GET /{appid}.json`

QQ 开放平台的域名校验文件。仅当配置 `BotAppId` 非空时匹配。

响应：`200 OK`

```json
{
  "appid": "1904835789",
  "name": "CaiBotWindy"
}
```

---

### 3.8 兜底与异常

| 状态码 | 触发条件 |
| --- | --- |
| `404` | 未匹配任何已注册路由 |
| `500` | 处理过程中抛出未捕获异常 |

## 4. 设备端接口 · WebSocket

### 4.1 连接地址

```
ws://<host>:<port>/server/ws/{group_open_id}/{server_type}/
```

路径参数

| 参数 | 类型 | 取值 | 说明 |
| --- | --- | --- | --- |
| `group_open_id` | string | OpenID | 绑定的群（URL 编码） |
| `server_type` | string | `tshock` / `tModLoader` / `bukkit` | 服务端类型 |

请求头

| 头 | 必填 | 说明 |
| --- | --- | --- |
| `Authorization` | 是 | 固定 `Bearer <token>`，token 由 `/server/token/{init_code}` 换取 |

**路径段数量必须恰好为 4**（`server` / `ws` / `{id}` / `{type}`），否则 `404`。

### 4.2 鉴权顺序与关闭码

校验按以下顺序进行，任一步失败即按对应关闭码断开。**为实现可读关闭码，服务端会先完成握手再关闭。**

| 顺序 | 校验项 | 关闭码 | 说明 |
| --- | --- | --- | --- |
| 1 | 是否提供 `Authorization` | `1008` | 缺失认证令牌 |
| 2 | 是否以 `Bearer ` 开头 | `1008` | 认证格式错误 |
| 3 | `server_type` 是否受支持 | `1008` | 不支持的服务器类型 |
| 4 | 令牌是否有效 | `4003` | 无效令牌，请重新绑定 |
| 5 | 令牌与群是否匹配 | `4003` | 令牌与群 OpenID 不匹配 |
| 6 | 是否为 WebSocket 升级请求 | HTTP `400` | 需要 WebSocket 升级请求 |

> 非 WebSocket 请求时，鉴权失败直接返回 HTTP `401` 与原因文本，不返回关闭码。

### 4.3 连接时序

```
适配插件                          CaiBotWindy
   │  GET /server/token/{code}  ──────►  │
   │  ◄──────  {token, group_open_id}    │
   │                                     │
   │  WS /server/ws/{gid}/{type}/        │
   │    Authorization: Bearer <token> ──►│
   │  ◄──────  101 Switching Protocols   │
   │                                     │
   │  ──── hello (to_bot) ────────────►  │  上报服务器信息
   │  ◄────── player_list (to_server) ── │  Bot 发起 RPC
   │  ──── player_list (响应) ─────────► │  复用同一 request_id
   │  ──── heartbeat (每 60s) ─────────► │  保活
```

保活：适配插件每 60 秒发送一次 `heartbeat`，仅用于刷新在线时间。

断线：连接关闭时该会话所有未完成的 RPC 请求会以「连接已断开」异常失败。

## 5. 数据包协议

### 5.1 通用封包

所有 WebSocket 帧均为单行紧凑 JSON（不缩进），适配插件单帧缓冲区只有 1024 字节。

```json
{
  "version": "2025.7.18",
  "direction": "to_server",
  "type": "player_list",
  "is_request": true,
  "request_id": "3f2a1b...",
  "payload": {}
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `version` | string | 协议版本，按包类型不同（见下表） |
| `direction` | string | `to_server`（Bot → 服务端）或 `to_bot`（服务端 → Bot） |
| `type` | string | 包类型（snake_case，见 [§5.3](#53-数据包清单)） |
| `is_request` | bool | `true` 表示参与请求-响应配对 |
| `request_id` | string \| null | 请求标识；非请求包显式为 JSON `null` |
| `payload` | object | 业务数据 |

### 5.2 请求-响应配对

- Bot 发起请求时生成 `request_id` 并注册等待器；
- 服务端响应时同样带 `is_request = true` 并复用同一 `request_id`；
- 服务端返回 `type = "error"` 时，等待器以 `ServerRpcException` 失败；
- 超时未响应同样抛出 `ServerRpcException`（`IsTimeout = true`）。

| 超时类型 | 配置项 | 默认值 |
| --- | --- | --- |
| 普通 RPC | `RequestTimeoutSeconds` | 10 秒 |
| 文件类 RPC（地图 / 世界文件） | `FileRequestTimeoutSeconds` | 60 秒 |

### 5.3 数据包清单

| type | 方向 | 用途 | 协议版本 |
| --- | --- | --- | --- |
| `hello` | to_bot | 服务端上报自身信息 | 2025.7.18 |
| `whitelist` | 双向 | 白名单校验（服务端问 → Bot 答） | 2025.7.18 |
| `player_list` | to_server | 查询在线玩家 | 2025.7.18 |
| `progress` | to_server | 查询世界进度 | 2025.7.18 |
| `look_bag` | to_server | 查询玩家背包 | 2025.7.18 |
| `world_file` | to_server | 下载世界文件 `.wld` | 2025.7.18 |
| `map_file` | to_server | 下载小地图 `.tmap` | 2025.7.18 |
| `map_image` | to_server | 获取地图预览图 | 2025.7.18 |
| `self_kick` | to_server | 让服务端踢出自己 | 2025.7.18 |
| `call_command` | to_server | 在服务端执行指令（远程指令） | 2025.7.18 |
| `unbind_server` | to_server | 通知服务端已解绑 | 2025.7.25 |
| `heartbeat` | to_bot | 保活（每 60 秒） | 2025.7.25 |
| `plugin_list` | to_server | 查询已装插件 / 模组 | 2025.7.25 |
| `rank_data` | to_server | 查询排行榜 | 2025.7.25 |
| `shop_condition` | to_server | 查询商店条件 | 2025.7.25 |
| `shop_buy` | to_server | 商店购买 | 2025.7.25 |
| `ping` | to_server | 延迟探测 | 2025.7.18 |
| `server_log` | to_bot | 服务端事件日志（广播到群） | 2025.7.18 |
| `server_file` | to_server | 读取服务端文件 / 目录 / 日志 | 2026.10.3.2 |
| `error` | 双向 | 错误处理 | 2026.2.14 |
| `unknown` | — | 未知包（忽略） | 2025.7.18 |

### 5.4 关键包详情

#### `hello`（服务端 → Bot）

连接建立后服务端主动上报。Bot 据此更新服务器档案并推送「服务器已上线」通知。

```json
{
  "server_name": "TShockWorld",
  "game_version": "1.4.5.8",
  "server_core_version": "TShock 6.2.1.0",
  "plugin_version": "2026.7.25",
  "system": "Windows",
  "enable_whitelist": true
}
```

#### `whitelist`（服务端 → Bot → 服务端）

请求（服务端发起，非请求型包）：

```json
{
  "player_name": "Steve",
  "player_ip": "1.2.3.4",
  "player_uuid": "uuid-xxxx"
}
```

响应（Bot 回包，仍为单向通知，不参与请求-响应配对）：

```json
{
  "player_name": "Steve",
  "is_admin": false,
  "whitelist_result": "accept"
}
```

`whitelist_result` 取值见 [§6](#6-白名单结果码)。

#### `player_list`（Bot → 服务端）

请求：`payload` 为空对象 `{}`

响应：

```json
{
  "server_name": "TShockWorld",
  "player_list": ["Steve", "Alex"],
  "current_online": 2,
  "max_online": 16,
  "process": "..."
}
```

#### `server_log`（服务端 → Bot）

```json
{ "message": "背包监控：Steve 持有物品超过阈值" }
```

Bot 会把该消息广播到绑定群，走的是出站消息队列，突发多条时自动摊平与重试。

#### `server_file`（Bot → 服务端）

机器人点播服务端磁盘上的文件 / 目录 / 日志，服务端读取后回传。适配插件版本 **2026.10.3.2** 起支持；机器人按 hello 上报的 `plugin_version` 做前置判定，版本不足时直接回提示而不发请求。

单独开一个包类型而不是复用 `server_log`，是因为两者方向相反：`server_log` 是服务端主动上报事件，本包是机器人主动请求、服务端应答，属于请求-响应链路。

请求：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `action` | string | `info` / `view` / `download`，缺省按 `info` 处理 |
| `path` | string | 目标路径；`info` 不需要。相对路径按服务端工作目录解析，支持环境变量展开 |

`action` 语义：

- `info`：回报服务端根目录、存档目录、当前世界文件名、日志目录、插件目录 —— 供指令在「不带参数」时做引导；
- `view`：目录返回条目清单（先目录后文件，各按名字排序），文本文件返回内容预览，二进制文件只返回元信息；
- `download`：取回文件本体；目录会被打包成 zip 一起回传。

响应（成功）：

```json
{
  "ok": true,
  "action": "download",
  "name": "TShockWorld.wld",
  "folder": false,
  "size": 18874368,
  "base64": "…"
}
```

`view` 的响应额外带 `kind`（`dir` / `text` / `binary`）、`path`、`name`、`mtime`、`count`、`text`、`truncated` 等字段；`info` 的响应带 `base_dir` / `save_dir` / `log_dir` / `world_dir` / `world_name` / `plugin_dir`。

响应（失败）：

```json
{ "ok": false, "error": "路径不存在：C:\\missing.txt" }
```

业务失败统一以 `ok = false` 返回，而不是抛成 `error` 包 —— 否则机器人侧只能拿到底层异常文本，分不清「路径不存在」这类正常错误和服务端内部故障。

`base64` 与 `world_file` / `map_file` 使用同一套两层编码：原始字节 → Base64 字符串 → gzip → 再 Base64，Bot 侧统一用 `BinaryCodec.Decode` 还原。

限制：

| 项 | 上限 | 原因 |
| --- | --- | --- |
| 单次回传原始字节 | 32 MB | 编码后膨胀约 1.8 倍，受 Bot 侧 64 MB 单包上限约束 |
| 文本预览 | 20000 字符 | 只用于「看一眼」 |
| 目录清单 | 300 条 | 同上 |
| 二进制预览 | 8 MB 以上跳过 | 读进来会把这一轮指令拖慢 |

路径不做白名单限制：能读到什么由 TShock 进程权限决定，调用侧已把相关指令限定为群管理员。在插件里再维护一份路径白名单，服务器换个目录结构就会静默失效，排查成本高于它挡下的风险。

#### `error`

```json
{ "error": "服务端处理请求时发生异常" }
```

Bot 侧行为：匹配到等待器则让它以异常失败；未匹配时仅在控制台记录。

## 6. 白名单结果码

由服务端 `whitelist` 请求返回，决定玩家能否进服。

| wire 值 | 枚举 | 含义 | 给玩家的提示 |
| --- | --- | --- | --- |
| `accept` | `Accept` | 允许进入 | — |
| `need_login` | `NeedLogin` | 需在群里完成登录确认 | 需要先在机器人中完成登录 |
| `not_in_whitelist` | `NotInWhitelist` | 无绑定记录 | 不在白名单中 |
| `not_registered` | `NotRegistered` | 有绑定但邮箱未完成验证 | 邮箱注册尚未完成 |
| `in_group_blacklist` | `InGroupBlacklist` | 命中群黑名单 | 位于群黑名单中 |
| `in_bot_blacklist` | `InBotBlacklist` | 命中机器人级云黑 | 位于机器人黑名单中 |
| `unknown` | `Unknown` | 未知状态 | 未知状态 |

校验顺序（三重检测）：

1. 云黑：全局（机器人级）优先于群级，四维度为角色名 / IP / 设备 UUID / OpenID
2. 角色名绑定：必须有绑定记录，否则 `not_in_whitelist`
3. 注册状态：走了邮箱注册的必须完成验证，否则 `not_registered`
4. 注册基准：首次进服记录 IP + 设备为基准；一个 IP / 一台设备最多注册 `RegisterLimitPerIp` 个角色（默认 2）
5. 历史环境：IP 与设备都在历史里则直接放行
6. 新环境：推登录确认卡片到群，管理员或本人点「确认登录 / 拒绝登录」

> 风控里的 IP / 设备是游戏侧上报的进服 IP 与客户端 UUID，**不是 QQ 用户的 IP**，两者完全无关。

## 7. QQ 指令接口

### 7.1 调用方式

- 群聊：直接发送 `/指令`，或 @ 机器人后发送
- 私聊：仅部分指令支持（图鉴搜索、白名单、签到、金币），需显式声明 `MessageScene.Private`
- 指令面板：群里输入 `/` 会拉起 QQ 指令面板（上限 24 条、每条 ≤ 8 中文字）
- 按钮：卡片按钮点击 = 发送对应指令文本（不是回调）

指令匹配维度：`适配器 : 场景 : 指令名`。未匹配时：
- 私聊 → 提示「没有这条指令」+ 私聊菜单
- 群内 @ → 提示「在的，不知道你想做什么喵~」
- 指令匹配到但执行报错 → 明确提示「指令执行失败」并附上错误摘要（不再混入未匹配兜底）

## 8. 配置接口

配置文件：`Config/CaiBotWindy.json`（相对 Windy 运行目录）。

写入方式：原子写入（先写临时文件再替换）+ 替换前自动备份（保留 3 份）。读取方式：文件损坏时自动回退到最近一份可用备份。

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `ListenPrefixes` | string[] | `["http://+:22338/"]` | HTTP 监听前缀，可用 `+` 表示全部网卡 |
| `PublicBaseUrl` | string | `""` | 对外基地址（不带结尾斜杠）。图鉴图标依赖它 |
| `BotAppId` | string | `""` | 机器人 AppID，用于 QQ 域名校验 `/{AppId}.json` |
| `OwnerOpenIds` | string[] | `[]` | 机器人所有者 OpenID，拥有全部权限 |
| `Operators` | string[] | `[]` | 全局管理员 OpenID（跨群生效） |
| `RequestTimeoutSeconds` | int | `10` | 普通 RPC 超时（秒） |
| `FileRequestTimeoutSeconds` | int | `60` | 地图 / 世界文件 RPC 超时（秒） |
| `BindCodeLifetimeMinutes` | int | `30` | 绑定验证码有效期（分钟） |
| `DownloadFileLifetimeMinutes` | int | `10` | 临时文件保留时长（分钟） |
| `MaxOutgoingFrameBytes` | int | `1000` | 单帧 JSON 软上限（字节），超出告警 |
| `MaxServersPerGroup` | int | `5` | 单群最多绑定服务器数 |
| `MaxPanels` | int | `20` | 单机器人最多指令面板数 |
| `DataDirectory` | string | `"Data"` | 图鉴数据目录 |
| `AssetDirectory` | string | `"Asserts"` | 图鉴素材目录（与官方 `assets/` 对应） |
| `StorageDirectory` | string | `"Config/CaiBotWindy"` | 数据存储目录 |
| `TShockLogDirectory` | string | `"../../TShock-Server/tshock/logs"` | TShock 日志目录（`/日志` 读这里） |
| `GroupJoinReview` | string | `"manual"` | 入群审核：`manual` / `auto` / `off` |
| `GroupJoinNotify` | bool | `false` | 自动处理后是否发群通知 |

### 8.1 Smtp 子对象

| 字段 | 类型 | 默认值 | 说明 |

## 9. 运维与诊断接口

### 9.1 `/性能`（别名 `xn` `perf`）

权限：管理员

返回内容：

- 调用统计（自启动起）：总调用数、失败数
- TOP 10 慢操作：次数、平均耗时、最大耗时
- 出站消息队列：`待发 / 已发 / 失败 / 丢弃`

关联机制：

| 阈值 | 行为 |
| --- | --- |
| ≥ 5 秒 | 控制台打印 `[慢请求]` |
| ≥ 15 秒 | 控制台打印 `[超时]` |

### 9.2 `/备份`（别名 `bf` `backup`）

权限：管理员

返回内容：`store.json` 与 `CaiBotWindy.json` 的备份份数与最近 5 份的时间、大小。

备份策略：

| 项目 | 文件 | 保留份数 |
| --- | --- | --- |
| 数据 | `Config/CaiBotWindy/store.json` | 7 |
| 配置 | `Config/CaiBotWindy.json` | 3（含敏感信息，少留副本） |

备份落在同级 `.backup/` 目录，命名为 `<原名>-<yyyyMMdd-HHmmss>.<扩展名>`。

## 10. 错误码汇总

### 10.1 HTTP 状态码

| 状态码 | 出现位置 | 含义 |
| --- | --- | --- |
| `200` | 全部 | 成功 |
| `400` | `/server/ws/` | 不是 WebSocket 升级请求 |
| `401` | `/server/ws/` | 鉴权失败且非 WebSocket 请求 |
| `403` | `/plugin/` `/assets/` | 路径非法（越权 / 含 `..`） |
| `404` | 全部 | 资源不存在 / 已过期 / 路由未匹配 |
| `500` | 全部 | 服务端内部异常 |

### 10.2 WebSocket 关闭码

| 关闭码 | 含义 |
| --- | --- |
| `1008` | 缺失认证令牌 / 认证格式错误 / 不支持的服务器类型 |
| `4003` | 无效令牌 / 令牌与群 OpenID 不匹配 |

### 10.3 白名单结果码

见 [§6 白名单结果码](#6-白名单结果码)。

### 10.4 指令层错误提示

| 场景 | 用户看到的回复 |
| --- | --- |
| 指令不存在 | ⛔ 没有这条指令 + 菜单引导 |
| 权限不足 | ⛔ 权限不足（需群主 / 群管理员 / 机器人管理员） |
| 仅限群聊 | ⛔ 该指令只能在群聊中使用 |
| 机器人未就绪 | ⏳ 机器人尚未就绪 |
| 未绑定服务器 | ⛔ 本群还没有绑定服务器 + 添加引导 |
| 服务器离线 | ⛔ 服务器 {名称} 当前离线 |
| 序号不存在 | ⛔ 序号 {n} 对应的服务器不存在或未连接 |
| RPC 超时 | ⏰ 服务器响应超时 |
| RPC 错误 | ⚠️ 服务器返回错误 |
| 指令执行异常 | ⚠️ 指令执行失败 + 错误摘要 + 「详情已记录到控制台」 |

> 最后一行是本次改造的重点：以前执行异常会与「未匹配」混为一谈，
> 导致系统故障时用户收到「不知道你想做什么」，既掩盖故障又误导。现在两者明确区分。
